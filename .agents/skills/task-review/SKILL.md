# Итоговое ревью GASS Configurator

**Вход.** Критерии задачи, база сравнения, относящийся к задаче diff и таблица проверок. При самостоятельном ревью установи эти входы по доступным данным и отметь пробелы. Учитывай незакоммиченные и новые файлы в согласованном объёме.

**Границы ревью.** Ревью выполняется в режиме чтения. Не изменяй файлы, включая код, тесты и конфигурацию. Не форматируй и не создавай коммиты. Результаты уже выполненных проверок используй как доказательства. Если запуск создаёт артефакты в проекте или меняет данные, передай его задаче реализации. Генерируемые результаты тестов не включай в состав изменений. Исправления выполняй только отдельной задачей реализации.

1. Сверь изменения с требованиями. Ищи нарушения поведения, инвариантов, совместимости, обработки ошибок и сохранности данных. Читай соседний код по конкретной гипотезе.
2. Для затронутых сценариев проверь применимые границы. [Инструкции](../../../AGENTS.md) и [карта](../../../docs/architecture.md) указывают контракты.
   - **Automated.** Сверь изоляцию Offline от SQL, проверки импорта, экспорта и целостности `.cfgproj`, повторное открытие и восстановление после прерванной записи. Для изменённых пакетов и данных проверь совместимость с прежними форматами.
   - **Manual (WPF).** Запуск, открытие изменённого экрана, навигация, ввод, валидация, ошибки, сохранение и повторное чтение. Если доступен Agent Desktop, зафиксируй реально выполненные GUI-шаги отдельно от ручной приёмки.
   - **Integration.** Для изменённых Online-сценариев используй выделенный SQL Server или LocalDB. Укажи среду и фактический сценарий. Прогоны на рабочей базе исключены.
3. Возьми существующие результаты из общей таблицы. Возврати в `task-workflow` только недостающие, устаревшие и не покрытые новым риском проверки. При самостоятельном ревью выполняй только необходимые проверки в согласованных границах.
4. Для подтверждённого замечания укажи серьёзность, путь и строку, сценарий, последствие и доказательство. Вынеси неподтверждённое отдельно. Сошлись на общую таблицу вместо копирования вывода. Исправления остаются в задаче реализации.

**Готово.** Один вердикт — `PASS`, `FAIL` или `NEEDS VERIFICATION`. `PASS` требует подтверждения обязательных проверок и отсутствия блокирующих замечаний.
