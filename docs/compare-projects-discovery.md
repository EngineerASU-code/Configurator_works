## Выводы

- Готовые компоненты покрывают чтение и редактирование одного источника, представление схемы и правила ключей. Step 7 даёт модель безопасного preview, но не имеет готового сравнения и переноса.
- Можно расширить открытие пакета без побочных эффектов и выставить узкий условный путь существующего Mode 3 update. SQL-строки с условием по ожидаемым значениям требуют учёта collation и точности типов. Простые создания возможны только при подтверждённой привязке класса, уникальном ключе и проверяемых зависимостях.
- Для сравнения нужны общая модель статусов, безопасное сопоставление, сводка и WPF. Для переноса нужны контроль целевого состояния, возможность отказаться от рискованных операций и подтверждение изменения ровно выбранного значения или сущности.
- Предположения о переносимости локального SQL ID, готовом Step 7 UI, наличии физических FK у всех отношений и полностью read-only штатном открытии пакета не подтвердились. Mode 3 параметры обычно представлены колонками, а составные сущности могут хранить их в отдельных строках.
- Пакет без доказательства происхождения не подтверждает идентичность строк по локальному ключу. Многотабличные объекты, неоднозначные зависимости, управляемые поля и потенциальные побочные эффекты требуют отдельного доменного пути записи.

## План и критерии

1. **R1, источники и Core.** Подключить независимые read-only чтения через существующие workspace, ввести общую модель, статусы и типизированные разницы. Проверить неизменность обеих сторон, области с ошибками, устойчивость ключей и совместимость схемы.
2. **R2, UI.** Добавить Compare в основную навигацию. Два сценария, выровненные стороны A/B, раздельные режимы, поиск, сводка, фильтры, детализация, прогресс и отмена. Проверить открытие WPF и право просмотра обоих разделов.
3. **R3, перенос.** Предлагать направление лишь для поддерживаемых операций Mode 3, показывать точные изменения и требовать подтверждения. Сверить целевую схему и данные, использовать штатную запись и откат. Проверить отсутствие побочных изменений и отказ при конфликте.
4. **R4, приёмка.** Чистый целевой diff, Core и Offline Integration, выделенная SQL LocalDB для Online Integration, фактическая WPF-приёмка Agent Desktop. Перед переходом между этапами проверять критические условия; не отмечать непроверенное как PASS.

Базовый фильтр xUnit дал 17 пройденных проверок. Тестовый скрипт вернул код 1 после тестов из-за блокировки очистки собственного временного файла. Проверка LocalDB вне песочницы подтвердила наличие утилиты и локальных экземпляров. Для задачи нужен выделенный тестовый экземпляр или база на стандартном LocalDB.
