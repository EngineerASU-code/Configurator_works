# Передача работы по GASS Configurator

23 ноября 2026. База изменений — `main`, `68dcca7374ffa824552ff23f58f8c29f5ec49e6b`. Task Workflow — `PARTIAL`.

## Реализовано

- Два профиля с обязательным входом. Для инженера доступны режимы 3 и 4, права на чтение и изменение проверяются отдельно.
- Защита удаления в Offline для сохранённых физических и ручных связей. При допустимой замене обновление ссылок и удаление входят в одну операцию. Диалог массового добавления переработан.
- Compare переносит поддерживаемые данные, классы, ручные связи, проектные текстовые списки и темы в обе стороны. Перенос проверяет актуальность предпросмотра. Compare открывается на мониторе главного окна.
- Program и Matrix используют специализированные редакторы и в Offline. FB поддерживает создание, правку, копирование и удаление определений. Совместимость экспорта FB с Siemens/TIA Portal не подтверждена.
- После проверки на реальной схеме удалена зависимость операций Program/Matrix от `TRY_CONVERT` при старом уровне совместимости SQL. В Online Matrix черновик допускает пропуск полей, для которых SQL задаёт значения по умолчанию.

## Проверено

- Release собран. xUnit с выделенным LocalDB — 404 из 404, без пропусков.
- На синтетическом пакете через WPF проверены удаление Area с заменой, перенос списка A → B и темы B → A, сохранение Program/Matrix и операции с FB. После закрытия файлов проверено содержимое пакетов.
- Реальная резервная копия восстановлена в выделенном LocalDB. Снимок для проверки Program/Matrix содержит 18 таблиц и 108 108 строк. В Offline через WPF созданы программа и дочерняя последовательность. Через репозитории проверены создание программы, добавление последовательности и перехода на существующий Step, а также создание матрицы с командой.
- Matrix на реальной схеме прошла создание, чтение и удаление команды и корневой записи через репозитории в обоих источниках. Offline требовал явного заполнения обязательных полей, для которых Online подставил SQL-значения по умолчанию.

## С чего продолжить

1. Восстановить исходный `.bak` на выделенный тестовый SQL Server/LocalDB. Резервную копию передать отдельно по разрешённому каналу. Учётные данные настроить штатной авторизацией. Для локальной сборки использовать .NET 10 SDK и .NET 8 Desktop Runtime.
2. Повторить создание Program в контексте PLC 1. Следующие номера могут быть заняты в связанных таблицах при отсутствии корневой записи. SQL-триггер вставки последовательности упирается в дубликат ключа рецепта. Сохранять существующие дочерние строки и учитывать их при поиске свободного номера.
3. Сверить побочные эффекты триггеров. SQL создаёт рецепт и параметры при вставке последовательности. В одном проверенном контексте это блокирует последующее удаление, тогда как Offline создаёт только явные записи. Защиту удаления не обходить. Определить поддерживаемые правила автоматического создания и проверки зависимостей в снимке.
4. Завершить WPF-цикл новой Matrix с дочерними командами на реальном снимке, повторное открытие созданной Program с дочерними записями и WPF-цикл в Online. Отдельно проверить SQL/Offline паритет значений по умолчанию, выгрузку в TIA Portal, фильтрацию и пагинацию режима 1 Offline.

Рабочая база не использовалась. Снимки, исходный backup, бинарные сборки, диагностические логи и локальные параметры подключения передаются отдельно от Git. RepTrack — отдельный проект и в передачу не входит.
