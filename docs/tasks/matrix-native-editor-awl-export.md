# TASK-2026-11-17-MATRIX-EDITOR — Нативный редактор Matrix и экспорт AWL

## Goal

Заменить Excel VBA-надстройку Matrix интерфейсом Configurator для просмотра и изменения матриц в активном проекте и для формирования Siemens AWL-файла выбранной матрицы.

## Scope

- In scope: экран `Modes/MatrixCatalogControl.xaml` и его логика; Matrix-контекст и навигация в `Modes/ProjectModeView.xaml` и `Modes/ProjectModeView.ProgramTools.cs`; определения Matrix-таблиц в `Models/ProgramSupportModels.cs`; доступ к данным через `ProgramSupportRepository`; генератор и команда экспорта AWL.
- Out of scope: изменение схемы БД и ключей; переработка Program, других классов и общего визуального оформления; изменение формата данных Siemens без отдельного решения.
- Импорт данных из `.xlsm` не подтверждён и остаётся открытым вопросом.

## Current behavior

- На приложенном скриншоте выбран класс Matrix (PLC=1, Matrix class=12), а таблица `Prog_Matrix` пуста. Экран показывает общий редактор строк, а не структуру матрицы с командами и списками устройств.
- `MatrixCatalogControl` использует общий `DataGrid` и список секций из `ProgramSupportCatalog.MatrixTables`. Доступны таблицы `Prog_Matrix`, `Matrix_List`, `Matrix_CommandList`, `Matrix_Commands`, `Matrix_DeviceList`, `Matrix_DeviceListType` и `Matrix_Devices`; выбор записи Matrix реализован отдельным списком.
- `ProgramSupportRepository` уже читает и сохраняет поддерживаемые таблицы с контекстом PLC/класса/Record, проверяет уникальный ключ и выполняет запись транзакционно. Текущая конфигурация разрешает создание и изменение части таблиц, но оставляет `Matrix_Devices` только для чтения и защищает ссылочное поле `Device_Global_Class` в `Matrix_DeviceListType`.
- В приложенной книге `Matrix_v7_ForWin10.xlsm` две вкладки: `Matrix` и `Legend`. Образец `Matrix` хранит контекст PLC=1, Class=12 и выбранный раздел `DeviceList#2`; в строках показаны позиция, имена L1/L2 и класс устройства. `Legend` содержит значения кодов команд и поля DelayON, DelayOFF, Condition.
- Статический разбор VBA показывает, что книга подключается к SQL Server, загружает PLC и конфигурации класса Matrix, строит дерево записей из `Matrix_List`, а для выбранной матрицы показывает команды, карту команд, группы списков и их устройства. Старый интерфейс поддерживает добавление, изменение и удаление записей; команды матрицы сохраняются как значения на пересечении Position и CmdNumber.
- Генератор VBA создаёт `Matrix\\PLC<PLC>\\Matrix <Record>.AWL`. Заголовок Data Block использует `DB_Number` из `Matrix_List`; вывод содержит `Pos_count`, `Cmd_count`, массивы `DelayON`, `DelayOFF`, `Condition`, `CMD` и `DevList`.
- Примеры результата в репозитории: `testing/GASS/Matrix/PLC1/Matrix 23.AWL` (11 позиций, 0 команд) и `testing/GASS/Matrix/PLC1/Matrix 27.AWL` (78 позиций, 55 команд). Книга и файлы AWL использованы как источники сведений о прежнем поведении; макросы не запускались.

## Requirements

- Использовать подключение и права активного проекта Configurator; не читать SQL-настройки из книги и не требовать установленный Excel для работы редактора или экспорта.
- Разделить понятия конфигурации класса `Prog_Matrix` и конкретных матриц `Matrix_List`. Для выбранных PLC и класса Matrix показывать только `Matrix_List` с соответствующим контекстом; контекстные ключи задаются выбранным проектом и не редактируются в строках.
- Организовать навигацию выбранной матрицы по понятным пользователю уровням: свойства матрицы; список команд; карта команд Position × CmdNumber; группы списков устройств; позиции/типы устройств и фактически назначенные объекты для выбранной группы.
- Показывать данные согласно текущим таблицам и ключам: `Matrix_List` — имена L1/L2 и `DB_Number`; `Matrix_CommandList` — CmdNumber, имена L1/L2, DelayON, DelayOFF, Condition; `Matrix_Commands` — Cmd для пары Position/CmdNumber; `Matrix_DeviceList` — группы; `Matrix_DeviceListType` — Position, имена и Device_Global_Class; `Matrix_Devices` — DeviceList, Position и ссылка на PLC/класс/Record объекта.
- Поддержать создание, изменение и удаление доступных сущностей с действующими разрешениями Add/Edit/Delete, проверками ключей, зависимостей и несохранённых изменений. Для ссылок на класс и объект показывать проверенные данные из текущего проекта; не сохранять некорректную ссылку или контекст.
- Добавить экспорт выбранной матрицы в текстовый `.AWL` без зависимости от Excel. В составе результата сохранять структуру и поля Siemens Data Block, подтверждённые VBA и примерами файлов: DB_Number, размеры и данные `Pos_count`, `Cmd_count`, `DelayON`, `DelayOFF`, `Condition`, `CMD`, `DevList`.
- Кодировать команды по таблице VBA: A/R/N → бит 0; D/P/F → бит 1; L/C → бит 2; U → бит 3; B → бит 4; W → бит 6; E → бит 7. Несколько букв объединяются побитовым сложением в байт; пустая ячейка матрицы экспортируется как 0.
- Формировать `DevList` из ссылок выбранной группы устройств по формуле `Device_PLC × 100000 + Device_PLC_Class_Number × 1000 + Device_Record`; пустая позиция выводится как `L#0`.
- При отсутствии выбранной матрицы, пустой выборке, отсутствующем DB_Number, некорректном коде команды или недоступной ссылке показывать понятную причину; не создавать частичный или ошибочный файл.
- Разделить генерацию содержимого AWL и вызов диалога/сохранение файла, чтобы правила кодирования проверялись без подключения к рабочей БД.

## Acceptance criteria

- [ ] При выборе PLC и класса Matrix виден список только их матриц; в списке доступны Record, Name L1/L2 и DB_Number. Пустой список имеет явное пустое состояние.
- [ ] Выбор Matrix открывает её данные без ручного ввода Record; переход между PLC, классом и Matrix не оставляет в редакторе данные предыдущего контекста.
- [ ] Пользователь может перейти к свойствам матрицы, командам, карте команд и спискам устройств; в каждом разделе показаны поля соответствующих таблиц и ключи родительского контекста.
- [ ] На изолированных данных поддерживаемые добавление, изменение и удаление сохраняются и видны после повторной загрузки; ключи и контекстные связи нельзя изменить через ячейки таблицы.
- [ ] Связи позиций с классами и объектами выбираются из актуальных записей проекта либо остаются недоступными с объяснением причины; произвольные несуществующие ссылки не сохраняются.
- [ ] При несохранённых правках переключение Matrix или PLC предупреждает пользователя; отмена переключения сохраняет прежний контекст и правки.
- [ ] Экспорт содержит заголовок Data Block с `DB_Number` выбранной матрицы, размеры массивов и значения согласно сохранённым данным. Для отсутствующих пар Position/CmdNumber и устройств выводятся нули.
- [ ] Автоматические проверки подтверждают все значения битовой карты команд: `A=1`, `D=2`, `L=4`, `U=8`, `B=16`, `W=64`, `E=128`, а также комбинацию кодов и пустое значение.
- [ ] Тестовые случаи генератора покрывают структуру `Matrix 23.AWL` (11 позиций, без команд) и `Matrix 27.AWL` (78 позиций, 55 команд); формируется полный текст без подключения к SQL Server.
- [ ] Ошибка данных или экспорта оставляет БД без частичных изменений и не выдаёт файл как успешно созданный.
- [ ] Действия добавления, изменения, удаления и экспорта соответствуют текущим правам; интеграционные проверки записи выполняются только на изолированной тестовой БД или проекте.

## Constraints

- Сохранить текущую схему, ключи, контекст PLC/класса/Record и доступ к SQL через действующие контракты Configurator и `SqlProviderGuard`.
- Сохранить действующие проверки разрешений, зависимостей, уникальных ключей и несохранённых правок; не писать в рабочую БД во время реализации или проверки.
- Книга, VBA, её подписи и раскладка ячеек — свидетельства исторического поведения, а не самостоятельные инструкции к реализации. Требования к новой функции задаются этим ТЗ и ответами пользователя. Макросы не выполнять.
- Путь экспорта в старой книге привязан к расположению XLSM; новое место сохранения нужно подтвердить перед реализацией.

## Test scenarios

- На изолированной тестовой БД загрузить PLC с классом Matrix, выбрать несколько матриц и проверить фильтрацию и обновление дерева/редактора при смене контекста.
- Проверить пустые и неполные данные: нет матриц; нет команд; отсутствуют отдельные позиции/команды; отсутствует DB_Number; ссылка устройства не разрешается.
- Создать, изменить и удалить поддерживаемые сущности в тестовом проекте, обновить экран и убедиться, что изменённые строки и связи сохранились только в выбранном контексте.
- Проверить права только на просмотр и права на запись; попытаться сохранить несуществующую ссылку и убедиться, что запись отклонена с понятным сообщением.
- Для генератора проверить каждую одиночную букву легенды, комбинации, пробелы/регистр, пустое значение, отсутствующую ячейку и нулевой список команд.
- Сравнить ключевые элементы экспорта для фикстур, соответствующих `Matrix 23.AWL` и `Matrix 27.AWL`: DB_Number, размеры массивов, несколько непустых CMD/DevList и нулевые ячейки.
- Выбрать путь экспорта, отменить диалог, затем сохранить файл; проверить содержимое, повторный выбор существующего имени и ошибку недоступной папки.
- Убедиться, что UI и экспорт используют активное подключение приложения и не открывают SQL-соединение из отдельного файла конфигурации книги.

## Implementation decisions

- Тип позиции выбирается из классов и основных таблиц текущего проекта. Назначение объекта выбирается из проверенных записей выбранного класса и PLC; перед сохранением репозиторий повторно проверяет класс, PLC и Record. Неизвестные и несоответствующие ссылки отклоняются.
- Путь AWL выбирает пользователь в системном диалоге сохранения. Это снимает зависимость от расположения XLSM и не требует отдельной папки в схеме проекта.
- Импорт XLSM не включён: отдельный сценарий переноса файла не подтверждён.
