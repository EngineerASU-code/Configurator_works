# TASK-2026-11-17-MULTI-ADD-WINDOW-UX — Отображение и компоновка окна массового добавления

## Goal

Исправить отображение вариантов PLC и сделать окно массового добавления компактным, центрированным и удобным при малом и большом числе строк.

## Scope

- In scope: окно массового добавления в режиме «Объекты проекта» (`Modes/MultiObjectEditorWindow.xaml`, `Modes/MultiObjectEditorWindow.xaml.cs`) и его вызов из `Modes/ProjectModeView.xaml.cs` при необходимости.
- Out of scope: изменение правил добавления объектов, генерации `Record`, валидации и записи данных; изменение других окон и экранов.

## Current behavior

- На приложенном скриншоте окно содержит строки для `Record`, `PLC` и `Name`, но пункты раскрытого списка PLC отображаются как `Configurator.BatchObjectPlcOption`, а не как понятные пользователю подписи PLC. Выбранное значение в поле при этом показывает `PLC01`.
- При нескольких строках таблица занимает большую область окна с заметным пустым пространством; кнопки действий находятся у нижней границы окна.
- В XAML окна заданы фиксированные размеры и строка таблицы, растягиваемая на свободную высоту. Скриншот служит свидетельством поведения, а не отдельной инструкцией.
- Пользователь уточнил предпочтение: компактное окно, центрированное относительно основного окна приложения.
- XAML содержит `DisplayMemberPath="Title"` и `SelectedValuePath="Key"`; фактический вид на скриншоте не соответствует ожидаемому отображению `Title`.

## Requirements

- В раскрытом списке PLC показывать пользовательскую подпись каждого варианта, а не имя CLR-типа. То же отображение должно работать для выбранного значения в строке.
- При выборе PLC сохранять его ключ (`Key`) в строке и передавать этот ключ в существующий обработчик добавления.
- При небольшом числе строк окно должно открываться компактным и центрированным относительно окна Configurator, оставаясь в пределах доступной рабочей области экрана.
- При добавлении строк окно может увеличиваться до доступной высоты; после достижения предела строки должны оставаться доступны через прокрутку. Пустое пространство таблицы не должно доминировать в компактном сценарии.
- Заголовки, значения строк, редактируемые поля и действия строки должны оставаться видимыми и доступными при обычном масштабе и поддерживаемом уменьшенном размере окна.
- Сохранить существующие действия добавления и удаления строк, автоматическое назначение `Record`, проверку значений, отмену и передачу подтверждённых строк вызывающему коду.

## Acceptance criteria

- [ ] Все варианты PLC в раскрытом списке отображаются понятными названиями из `Title`, без текста `Configurator.BatchObjectPlcOption`.
- [ ] После выбора PLC в строке остаётся выбранная подпись, а в передаваемых данных используется соответствующий `Key`.
- [ ] Окно открывается компактным и центрированным относительно основного окна, полностью внутри доступной рабочей области.
- [ ] При одной-нескольких строках нет чрезмерно пустой области таблицы; кнопки отмены и добавления остаются видимыми.
- [ ] При увеличении числа строк окно не выходит за границы рабочей области; дополнительные строки доступны прокруткой.
- [ ] Заголовки и элементы таблицы не перекрывают друг друга; PLC и имя объекта доступны для редактирования, действие удаления доступно для каждой строки.
- [ ] Добавление/удаление строк, генерация `Record`, валидация, отмена и подтверждение сохраняют прежнюю семантику.
- [ ] Ручная проверка выполнения добавления проводится только на изолированном тестовом проекте или тестовой БД.

## Constraints

- Не менять ключи PLC, правила генерации `Record`, проверку дубликатов и права доступа.
- Не записывать тестовые строки в рабочую базу данных.
- Компактное размещение должно учитывать DPI-масштабирование и границы рабочего стола.

## Test scenarios

- Открыть массовое добавление с несколькими вариантами PLC и проверить подписи в выпадающем списке, выбранном поле и значениях, переданных обработчику.
- Открыть окно с одной строкой, проверить компактный размер и центрирование относительно основного окна.
- Добавить несколько строк до заполнения окна и выше доступной высоты; проверить рост окна, прокрутку и доступность нижних кнопок.
- Проверить редактирование `Record`, выбор PLC для каждой строки, имя, удаление строки, валидацию, отмену и подтверждение.
- Повторить визуальную проверку при стандартном и увеличенном DPI, а также при уменьшенной поддерживаемой ширине окна.
- Проверить реальную запись только на изолированном тестовом проекте или тестовой БД.
