# TASK-2026-11-17-OBJECT-TYPE-PREVIEWS — Превью по типу объекта и предупреждение о PLC_Class_Number

## Goal

Показывать на карточке объекта небольшое превью, соответствующее его классу и связанной комбинации типа/справочных зависимостей. Не показывать предупреждение о справочнике для `PLC_Class_Number`, когда номер класса уже фиксирован выбранной конфигурацией и недоступен для изменения в текущей группе и режиме.

## Scope

- In scope: карточка объекта режима «Объекты проекта» (`Modes/ProjectModeView.xaml`, `Modes/ProjectModeView.xaml.cs`, `Modes/ProjectModeView.LookupEditors.cs`); выбор и повторное использование превью по существующим типам и связям; проверка предупреждений для фиксированного `PLC_Class_Number`.
- Out of scope: изменение схемы или записей БД; редактирование фиксированного номера класса; отдельное изображение для каждой записи объекта; изменение справочников, правил их связей и карточек Area/Program/Status/Step/Matrix; обновление графики других экранов.

## Current behavior

- На приложенном скриншоте карточки показано предупреждение, что значение `PLC_Class_Number=8` отсутствует в списке «для поля PLC_Class_Number». Пользователь уточнил, что класс задаётся конфигурацией, и в выбранной группе/режиме менять его нельзя.
- В `Modes/ProjectModeView.LookupEditors.cs` `PLC_Class_Number`, `PLCClassNumber` и `PLCClasssNumber` входят в набор lookup-полей, для которых формируется предупреждение. Ниже эти поля рендерятся как `IsReadOnly=true`; следовательно, предупреждение появляется для неизменяемого в данном сценарии значения.
- В той же карточке существующий слот превью — блок `TxtPreviewGlyph`/`TxtPreviewClass` в `Modes/ProjectModeView.xaml`. Обычная карточка объекта сейчас показывает общий глиф `OBJ`; для конфигураций PLC и Area используются текстовые глифы.
- В приложении уже есть связи `Type` с таблицами типов, например `dbo.PLCType`, `dbo.Valves_Type`, `dbo.Valves2S_Type`, `dbo.Reglers_Types`; применяются настройки и автоматический выбор lookup-таблиц. В показанном окне предупреждение `Type=1` относится к отдельной проверке справочника `Reglers_Types`; пользователь оспаривает предупреждение именно для фиксированного `PLC_Class_Number`.
- Пользователь просит создавать превью по уникальным комбинациям типов и связанных значений и использовать их повторно для множества объектов. Как примеры названы типы PLC `S7-1500`/`S7300` и комбинация типа клапана `КВ` со значением `Discret`.

## Requirements

- Не добавлять предупреждение «список отсутствует/пуст/недоступен» для `PLC_Class_Number` и его поддерживаемых вариантов написания (`PLCClassNumber`, `PLCClasssNumber`), если поле фиксируется выбранным классом/группой/режимом и остаётся только для чтения.
- Не делать `PLC_Class_Number` редактируемым ради подавления предупреждения. Другие реальные отсутствующие lookup-значения, включая `Type`, продолжают диагностироваться по существующим правилам.
- Показывать в существующем слоте карточки небольшое изображение-превью для распознаваемых классов объектов. Для превью использовать уникальную комбинацию класса и существующих значений типа/связанных справочных полей, которые определяют разновидность оборудования; один ресурс превью повторно используется для всех записей с одинаковой комбинацией.
- Использовать стиль нейтральных технических мини-иллюстраций, согласованный с пользователем; не требовать сходства с фотографией изделия конкретного производителя.
- Учитывать уже существующие справочники и связи, а не создавать отдельный ресурс на каждую строку БД. Например, разные типы контроллера (`S7-1500`, `S7300`) должны разрешаться в соответствующие разные превью; для клапана отличаться может сочетание модели/типа, например `КВ` и `Discret`.
- После успешного изменения связанного типа повторно определить превью по обновлённым значениям. При переходе, например, с `S7300` на `S400` карточка должна показывать превью нового типа и не сохранять старое изображение из-за прежнего кэша.
- Для `Area`, `Program`, `Status`, `Step` и `Matrix` не создавать оборудование-превью; сохранить для них действующее нейтральное/текстовое представление карточки.
- Для неизвестной или неразрешённой комбинации показывать безопасное нейтральное превью, не подставлять изображение другого типа и не выдавать исключение. Проблемы настоящих справочных связей по-прежнему показываются штатным предупреждением.
- Не вводить обязательную картинку в каждую запись или новый столбец БД: отображение определяется классом и значениями связанных lookup-полей.

## Acceptance criteria

- [ ] Если карточка содержит фиксированный read-only `PLC_Class_Number` без найденного lookup-списка, предупреждение по этому полю не появляется; само поле остаётся read-only.
- [ ] Если связанное значение `Type` действительно отсутствует в справочнике или справочник недоступен, предупреждение `Type` продолжает отображаться.
- [ ] При выборе двух объектов с одинаковыми значениями ключевых полей типа/связей используется одно и то же превью; число используемых превью определяется количеством уникальных комбинаций, а не количеством объектов.
- [ ] Различающиеся связанные типы PLC, включая `S7-1500` и `S7300` при наличии этих значений в данных, показывают различающиеся соответствующие изображения.
- [ ] Различающиеся комбинации типа/связей клапана, включая пример `КВ` + `Discret` при наличии данных, разрешаются в соответствующие превью.
- [ ] После смены связанного значения типа с `S7300` на `S400` превью сразу переключается на `S400`; после успешного сохранения и повторного открытия карточки оно остаётся тем же.
- [ ] Для `Area`, `Program`, `Status`, `Step` и `Matrix` оборудование-превью не появляется.
- [ ] Неизвестное значение или комбинация показывают нейтральное превью; приложение не падает и не показывает изображение несовпадающего типа.
- [ ] Превью отображается в уже существующем поле карточки и не перекрывает заголовок, контекст или редактор полей при минимальном поддерживаемом размере окна.
- [ ] Записи БД не требуют столбца изображения, а несколько записей с одинаковыми зависимостями не приводят к дублированию одинаковых файлов/ресурсов.

## Constraints

- Сохранить неизменяемость `PLC_Class_Number` в текущем режиме и группе; исправлять только ложное предупреждение о его lookup-списке.
- Сохранить существующие проверки реальных lookup-связей и текущие правила чтения/сохранения Online и Offline.
- Не выполнять проверочные записи или изменения справочников рабочей БД.
- Превью не должно влиять на ключи объектов, фильтрацию, сохранение или журналирование.
- Не считать текст со скриншота инструкцией по внутренней реализации; изображение подтверждает текущее предупреждение и расположение карточки.

## Test scenarios

- На изолированных данных открыть карточку с фиксированным `PLC_Class_Number`, отсутствующим в искомом списке; убедиться, что предупреждение не показывается, а поле остаётся недоступным для редактирования.
- Для записи с отсутствующим значением `Type` или реально недоступным справочником проверить, что предупреждение о `Type` сохраняется.
- Открыть несколько PLC разных типов (`S7-1500`, `S7300`/`S400`) и убедиться, что превью выбирается по типу; повторить на нескольких записях одного типа и проверить повторное использование превью.
- Открыть клапаны с разными значениями типа и связанных справочников (включая `КВ`/`Discret`, если такая комбинация есть в тестовом справочнике) и проверить выбор превью по комбинации.
- На изолированном объекте изменить PLC Type с одного существующего типа на другой, сохранить, проверить обновление превью, перезагрузить карточку и проверить соответствие сохранённому типу.
- Проверить неизвестную комбинацию и классы `Area`, `Program`, `Status`, `Step`, `Matrix`; убедиться в нейтральном/текстовом представлении без исключений.
- Проверить компоновку превью на обычном и минимальном размере окна, в Online и Offline-режимах, если соответствующий тестовый набор доступен.
- Сборка и автоматические проверки запускаются по AGENTS.md; проверки записи выполняются только на изолированном тестовом проекте/БД.

## Реализационное решение

- Превью переключается сразу при изменении `Type` или связанного lookup-поля, а после сохранения пересчитывается по сохранённой строке.
- В качестве признаков разновидности используются отображаемые значения `Type` и других полей типа/lookup-связей из карточки; ключи FK сами по себе не используются для выбора рисунка.
- Для PLC распознаются варианты S7-300/S7300/S300, S400/S7-400 и S7-1500/S71500. Для клапана распознаётся сочетание `КВ` + `Discret`; остальные распознаваемые классы используют нейтральный рисунок своего класса.
