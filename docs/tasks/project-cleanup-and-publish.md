# TASK-2026-11-17-CLEANUP — Подготовка проекта к публикации

## Цель и границы

Проверить структуру рабочей папки и репозитория `configurator/`, сохранить отдельный отчёт, удалить подтверждённо устаревшие материалы, использованные ТЗ и производный кеш, подготовить и отправить согласованный конечный проект в существующий origin обычным push.

Сохранить текущие прикладные изменения, исходники, необходимые ресурсы, тесты, пользовательские данные, эталоны и требования с неподтверждённой приёмкой. Не читать БД, профили провайдеров и конфиги с секретами. Не менять историю Git и удалённые ветки. Служебные инструменты родительской папки не являются частью поставки приложения.

## Критерии приёмки

1. Отдельный отчёт описывает структуру, текущие изменения, удалённые материалы, сохранённые ограничения и фактические результаты проверок.
2. Удалены старые поставочные сборки и производные кеши; завершённые разовые документы свёрнуты в отчёт. Незавершённые требования и эталоны сохранены.
3. README, навигация и gitignore соответствуют итоговому дереву. Удаление не затрагивает рабочие данные и runtime-ресурсы.
4. Restore, Release build и все существующие регрессионные тесты проходят; найденные блокирующие ошибки устранены. Ручная UI/SQL приёмка обозначена отдельно.
5. Проверены состав публикации, отсутствие локальных секретов и синхронность origin. Только выбранные пути включены в коммит.
6. Выполнено независимое итоговое ревью. Push без force выполняется после необходимого подтверждения публикации в default branch; фактический результат и SHA сообщаются пользователю.

## Проверки и открытые вопросы

`dotnet restore Configurator.slnx`, Release build, тесты с отдельными TEMP/TMP, `git diff --check`, проверка ссылок и ресурсов, проверка путей и содержимого выбранных файлов на секреты без вывода значений.

У origin публичная видимость и default branch `main`; отдельное подтверждение конечного состава публикации требуется навыком github-push. Старые ТЗ с непроверенными UI/SQL сценариями нельзя обозначать выполненными.
