# AI_lobby: состав папки и принцип работы приложения

Дата изучения: 12 ноября 2026 года. Описание составлено по исходникам и конфигурации проекта; приложение, сборка и тесты в рамках этого обзора не запускались, подключения к БД не выполнялись.

## Назначение

В папке находится **GASS Configurator** — настольное Windows-приложение для просмотра и изменения проектных данных SQL Server, описания классов, полей и связей, работы с объектами проекта. Версия в `GASS_Configurator/Configurator.csproj` — **6.0.1**. Технологии: C#, .NET 8, WPF/XAML.

Приложение поддерживает два источника данных: **Online** — подключённая база SQL Server; **Offline** — локальный переносимый проект `.cfgproj` со снимком данных и структуры.

## Принцип работы

1. **Запуск и доступ.** `App` применяет тему и инициализирует `UserAuthorizationService`. При первом запуске предлагает настроить администратора, затем открывает `MainWindow`. Главное окно запускает диалог входа; открытие Offline-проекта предусмотрено без Online-входа. Права определяются пользователем, ролью и каталогом разрешений.
2. **Выбор источника.** В Online пользователь задаёт сервер, SQL-учётные данные и базу. В Offline выбирает `.cfgproj`. `ProjectDataSourceContext` назначает адаптеры чтения, записи и архитектуры; при смене проекта отменяет операции предыдущего рабочего пространства.
3. **Работа с данными.** Раздел «БД проекта» показывает таблицы, строки, фильтры и страницы; позволяет добавлять, изменять, дублировать и удалять данные в пределах доступных прав. `TableViewModel` и `DatabaseService` обслуживают табличный Online-путь; для Offline главное окно использует локальные записи проекта.
4. **Работа со структурой и объектами.** «Структура БД» использует `TemplateArchitectureView` для классов, полей и связей. «Объекты проекта» использует `ProjectModeView` и общее рабочее пространство для объектов и справочников. Анализатор строит граф по схеме БД и логическим правилам; сам анализ не создаёт SQL-связи.
5. **Сохранение и история.** Online-операции обращаются к SQL Server. Offline-операции меняют локальный снимок; предусмотрены сохранение в открытый файл и автосохранение с интервалом таймера 2 секунды. `ChangeJournalService` хранит историю изменений и поддерживает восстановление с проверками конфликтов; `ActionLogService` ведёт краткосрочную историю в памяти. Экспорт `.xlsx` формируется средствами ZIP/XML без установленного Excel.

«Редактор FB-блоков» в текущем XAML — заглушка с сообщением о недоступности редактирования. В `Core/Synchronization` реализованы модели и проверки плана, но полноценный механизм переноса Offline-изменений в Online и его интеграция с интерфейсом не обнаружены. Обычные Online CRUD-операции реализованы отдельно.

## Зависимости

Основные связи исполнения:

```text
App → UserAuthorizationService → MainWindow
MainWindow → панели / TableViewModel → DatabaseService → SQL Server
MainWindow → TemplateArchitectureView / ProjectModeView
ProjectModeView → IProjectWorkspace → ProjectWorkspace
    ├─ OnlineProjectDataSource / OnlineProjectCrudDataSource → SQL Server
    └─ OfflineProjectDataSource → ConfiguratorProject → ProjectPackageService → .cfgproj
ClassArchitectureService → SystemClassCatalog + TemplateLibraryStore
Интерфейс и CRUD → PermissionPolicy / ChangeJournalService
```

Это логические слои одного приложения: `Core`, `Application`, `Infrastructure` и `Services` не выделены в самостоятельные проекты. Код сочетает модели представления с существенной логикой в обработчиках WPF.

| Внешняя зависимость | Версия в проекте | Назначение |
| --- | --- | --- |
| .NET / WPF | `net8.0-windows` | Исполнение и Windows-интерфейс. Для сборки нужен .NET SDK с поддержкой WPF. |
| `Microsoft.Data.SqlClient` | 7.1.0 | Подключения и запросы SQL Server. Сервер нужен для Online; локальный снимок работает без него. |
| `Microsoft.SqlServer.TransactSql.ScriptDom` | 161.8901.0 | Разбор и проверка запросов SQL-редактора. |
| `Newtonsoft.Json` | 13.0.4 | JSON-сериализация, в частности хранилища пользователей. Также используется встроенный `System.Text.Json`. |
| `Microsoft.NET.Test.Sdk` / `xunit` / `xunit.runner.visualstudio` | 17.12.0 / 2.9.2 / 2.8.2 | Инфраструктура тестов; основной программе не требуются. |

SQL-редактор допускает одиночные `SELECT`, `INSERT`, `UPDATE`, `DELETE`; для `UPDATE` и `DELETE` требует `WHERE`. DDL, процедуры и административные команды запрещены политикой приложения. `SqlProviderGuard` блокирует новые SQL-подключения при активном Offline-источнике.

## Форматы и хранение

`.cfgproj` — ZIP-пакет с JSON, текущая версия формата при сохранении — **2**, предусмотрено чтение версии 1. Основные разделы:

- `manifest.json` — идентификатор, имя, версия и даты проекта;
- `project/settings.json`, `mappings.json`, `architecture.json` — настройки, сопоставления с таблицами и архитектура;
- `project/graph-relations.json`, `filters.json`, `text-lists.json` — связи, фильтры и справочные списки;
- `data/local-snapshot.json`, `baseline.json`, `table-schemas.json` — рабочие записи, исходный снимок и схемы таблиц.

Учётные данные подключения не должны попадать в переносимый пакет; сервис упаковки проверяет его содержимое и формат. Сохранение использует временные файлы, замену или защищённую запись с восстановлением в зависимости от способа открытия.

Пользовательские файлы создаются во время работы и не обязательно находятся в исследуемой папке:

- `%APPDATA%/Configurator/users.json` — пользователи и роли; пароли хэшируются PBKDF2-SHA256.
- `%APPDATA%/Configurator/settings.json` — параметры SQL-подключения; сохраняемый пароль защищается Windows DPAPI для текущего пользователя.
- `%APPDATA%/Configurator/GraphRelations/` — Online-настройки связей по серверу и БД.
- `%LOCALAPPDATA%/Configurator/ChangeJournal/Online/` — Online-журналы по серверу и БД; Offline-журнал хранится внутри архитектуры проекта.
- `appsettings.json` рядом с исполняемым файлом — оформление и общие настройки интерфейса.

## Сборка и проверка

Из каталога `GASS_Configurator` в Windows можно выполнить:

```powershell
dotnet build .\Configurator.csproj -c Release
dotnet test .\tests\Configurator.Security.Tests\Configurator.Security.Tests.csproj -c Release
```

Альтернатива — `Run-Configurator-Tests.ps1`. Наличие готовых файлов в `bin` и `obj` само по себе не подтверждает успешную сборку и прохождение тестов текущих исходников. Резервные копии `.bak` при изучении не восстанавливались; их таблицы, связи и соответствие приложению не проверялись.
